# ResearchAssistant 仓库完善计划

## 梳理结论（背景）

本地优先科研助理工作台（比赛演示向）：桌面 Tauri 2 + React 19（`src/`、`src-tauri/`），移动端 Expo RN（`mobile-app/`），共享协议包 `packages/contracts`，桌面内嵌 axum 服务经 LAN / Tailscale / Cloudflare Tunnel 与手机配对。

核心问题：

1. **未提交风险**：1.1.15→1.1.18 四个版本的发布内容（27 文件，+2879/−839）全部在工作树未提交，HEAD 停在 1.1.14。
2. **巨型单体**：`research_memory.rs` 8775 行、`lib.rs` 6952 行（86 命令）、`mobile.rs` 5808 行（35 路由+内嵌 HTML）、`App.tsx` 4466 行（58 useState）、`PdfReader.tsx` 4316 行、`App.css` 8707 行、mobile `chat.tsx` 2661 行。
3. **死代码**：`src-tauri/src/rag.rs` 382 行无 `mod rag` 声明（未编译）；`mobile-app/app/pdf-reader.tsx` 约 1180 行注释旧实现；`modelMirrors.ts` qwen3 条目重复；`contracts/index.ts` 两个接口重复声明。
4. **测试/门禁缺口**：桌面前端零单测；mobile 3 个测试套件 CI 只跑 1 个；`check-desktop-pdf-selection.mjs` 字符串断言式伪测试且未接入 CI；无 ESLint；版本 8 处手工同步。
5. **卫生**：根目录 4 个未跟踪 `build-log*.txt`（未 gitignore）、`mtest` 垃圾符号链接、`findings.md` 记录过时。
6. **安全**：CSP `null`；API key 明文存 `app_data_dir` JSON；移动端 HTTP 明文（有 device token，演示可接受）。

计划分 5 个阶段，每阶段独立提交、独立里程碑，可随时停在任意阶段。

## 阶段 1：工程化门禁

2. 引入 ESLint 9 flat config（typescript-eslint + react-hooks），root 与 mobile-app 各一份，规则先 warn 起步（重点 unused-vars、hooks deps），加根级 `lint` 脚本并接入 CI

4. 新增 `scripts/bump-version.mjs`：一条命令同步全部 8 处版本号（3×package.json、app.json version+versionCode、tauri.conf.json、Cargo.toml、Cargo.lock、build.gradle versionName+versionCode），完成后自动跑 `check:release-version` 校验；README 补发布流程说明

**里程碑 M2**：CI 全绿，含 lint 与全部测试套件。

## 阶段 2：测试补齐（按风险排序）

1. 引入 vitest（桌面端）：把 `PdfReader.tsx` 选区边界计算（character Range 遍历、`getSelectionClientRects` 坐标系）抽为 `src/lib/pdfSelection.ts` 纯模块并写单测，替代字符串断言脚本；`modelMirrors.ts` 补单测
2. `mobile.rs` 关键路由集成测试：用 axum `tower::ServiceExt::oneshot` 对 `/pair`、`/bootstrap`、inbox、chat 流式路由做无端口测试（token 通过/拒绝两路）
3. CI 增加前端 vitest job

**里程碑 M3**：重构有安全网。

## 阶段 3：架构重构（渐进式，行为不变、小步提交）

Rust 端（收益最大，先做）：

1. `mobile.rs` 拆分：`router.rs`（路由表）、`pairing.rs`（配对+token）、`tunnel.rs`（Tailscale+Cloudflare）、`chat.rs`（流式聊天，与桌面端去重）、`pdf_viewer.rs`（内嵌 HTML 移到 `include_str!` 资源文件）
2. `lib.rs` 按域拆 commands：`workspace` / `ollama` / `pdf_ai` / `drafts` / `settings`，`lib.rs` 保留 `run()` 与状态注册
3. `research_memory.rs` 拆分：`db.rs`（SQLite schema+DAO）、`vector.rs`（LanceDB）、`ingest.rs`、`graph.rs`、`providers.rs`

前端：4. `App.tsx` 拆自定义 hooks + Context（`useWorkspace`、`useIngest`、`useOllamaRuntime`、`useMobilePairing`、`useSettingsModal`），目标 <800 行 5. `PdfReader.tsx` 拆：页面虚拟渲染、选区/高亮、注释持久化三个子模块（配合阶段 2 纯模块）6. `App.css` 按域拆分文件（视觉回归风险最高，最后做）

移动端：7. `chat.tsx` 参照 `pdfReaderCore` 范式抽 `useChatThread` / `useStreaming` hooks 与子组件

**里程碑 M4**：最大文件 <1500 行，全部既有测试通过。

## 执行方式

- 每个动作小步提交（conventional commit，走现有 husky/commitlint 流程）
- 阶段 0 → 1 → 2 顺序执行；阶段 3 各文件拆分相互独立，可并行/暂停；阶段 4 按需
- 全程不改任何业务行为，重构以测试与类型检查护航（`tsc --noEmit`、`cargo test --lib`、mobile 三套件、阶段 2 新增 vitest）
