# 移动端交互与渲染修复方案

## 目标定义

修复移动端 `/`、`@` 输入可见性和 PDF 解释上下文乱码；调整设置页声明；让创新生成具备明确入口；统一渲染聊天、创新、卡片与笔记中的 Markdown，并交付 1.1.10 桌面与 Android 版本。

## 功能分解

1. 命令与论文选择在输入栏中显示可见 Token，发送时仍使用结构化协议并剥离显示 Token。
2. 桌面端对 PDF 页面文本执行 Unicode 与行质量清洗；不可靠上下文降级为无页面上下文解释。
3. 聊天聚合页增加“创新”子视图，汇总会话中带 `innovationAnalysis` 的回答和 Idea Map 保存状态。
4. 引入移动 Markdown 渲染组件，覆盖助手回答、创新详情、知识卡片和论文笔记。
5. 设置页声明准确描述本地优先、桌面推理、资料同步与非医疗建议边界。

## 实施步骤

1. 核对设置页、消息渲染、创新字段和现有依赖。
2. 实现输入 Token 帮助函数、上下文清洗函数及单元测试。
3. 实现 Markdown 组件和创新页内视图，调整设置声明。
4. 更新仓库文档与版本。
5. 执行 TypeScript、Rust、Web、NSIS 和 Android release 验证。

## 验收标准

- 点击 `/` 或 `@` 后字符立即进入输入栏；选择候选后输入栏显示完整选择，发送正文不重复携带这些 Token。
- 页面上下文不再显示 `�` 密集乱码；低质量片段明确降级，不影响术语解释主体。
- 聊天页顶部可以直接进入“创新”，浏览历史创新点并回到对应会话。
- Markdown 标题、列表、粗体、引用和代码在移动端有结构化样式。
- 设置页声明与当前本地桌面 companion 架构一致。
