# 自然滑选、创新图谱与演示论文整理方案

更新日期：2026-08-10

## 1. 目标

本轮改造包含三个目标：

1. 将移动 PDF 的矩形框选替换为符合手机阅读习惯的线性选字；不要求长按，不受 PDF text layer 的 DOM 顺序影响。
2. 将移动会话中的 A+B 分析持久化为 Idea Map 创新节点，并显示若干论文证据节点指向创新点的可追溯边。
3. 将当前工作区论文整理为小型演示集。用户后续明确授权物理删除，因此最终保留 6 篇并删除其余 114 篇 PDF；知识卡片、会话和 Research Memory 数据库保持不变。

## 2. 当前状态与问题

### 2.1 PDF 选区

- 原生浏览器 Range 会按照 DOM 顺序连接起点与终点；双栏 PDF 的 DOM 顺序可能与视觉阅读顺序不同，因此会夹入上方作者单位或左栏。
- 当前几何矩形选择能避免跨栏错选，但它属于区域选择，不符合用户对连续文字选择的操作预期。
- 正确目标是“起点字符到终点字符”的线性选择，同时按视觉行和阅读区域排序。

### 2.2 A+B 与 Idea Map

- A+B 分析当前只保存在移动聊天消息中，证据通过 `[A1]`、`[B1]` 和 `citations` 持久化。
- Idea Map 当前只消费 `idea_candidates`，并从 Challenge、Module、Task、Pipeline 等概念节点生成 `inspired_by` 或 `resolves` 边。
- 当前 `materialize_ideas` 会执行 `DELETE FROM idea_candidates`。如果直接把聊天 Idea 写入该表，下一次索引或图谱刷新会将其删除。
- Idea Canvas 当前没有 `paper` 节点，也没有论文到 Idea 的证据边。

### 2.3 论文数据

- 工作区共有 120 份 PDF，合计约 692.01 MiB。
- Research Memory 数据库只登记了 2 篇论文：
  - `Tejada-Lapuerta 等 - 2025 - Causal machine learning for single-cell genomics`
  - `Tan 等 - 2025 - Integration of Single-Cell Analysis and Bulk RNA Sequencing Data Using Multi-Level Attention Graph Network...`
- 其余论文主要通过工作区扫描进入移动“论文”列表，并不是已完成索引的 Research Memory 证据。
- 当前存在 6 组内容哈希完全相同的重复 PDF。
- 移动“论文”列表过长的直接原因是 companion service 会递归追加所有工作区 PDF，而不是 Research Memory 已索引过多。

## 3. 自然线性滑选设计

### 3.1 交互

- 工具栏将“滑选”改为“选字”。进入选字模式后，用户直接按下并拖动，不要求长按。
- 按下位置确定字符锚点，拖动位置确定焦点；高亮表现为普通连续文字选区，不显示矩形边框。
- 单击选择当前词。
- 松手后显示起点和终点手柄；拖动任一手柄可继续微调选区。
- 手指接近阅读区上、下边缘时允许低速自动滚动。
- 退出选字模式后保留当前高亮和 AI 操作栏；翻页、重新打开文件或开始新的系统选区时清除旧选区。

### 3.2 视觉文本模型

在当前页 text layer 渲染完成后构建只读的 `VisualTextMap`：

1. 提取每个可见字符的页面坐标、所属文本节点和 UTF-16 偏移。
2. 按基线与垂直重叠把字符聚合为视觉行。
3. 根据水平重叠、行间距和稳定垂直空白带，把视觉行聚合为阅读区域；正文右栏、侧栏、作者单位分别形成独立区域。
4. 区域内按从上到下、同行从左到右排序；全宽标题作为独立跨栏区域。
5. 缓存当前页结果，翻页或 viewport 尺寸变化时失效。

拖动时通过最近字符命中锚点和焦点：

- 两端位于同一阅读区域时，选择该区域视觉顺序中的连续字符区间。
- 两端位于不同区域时，焦点钳制在锚点所属阅读流，并提示“跨栏内容请分次选择”；不能仅因 DOM 节点相邻而跨栏。
- 自定义高亮层按字符 Range 的 `getClientRects()` 绘制，但选区成员和文本拼接完全由 `VisualTextMap` 决定。

### 3.3 性能与兼容

- 只处理当前页，并在 text layer ready 后按需构建。
- 指针移动阶段只更新锚点、焦点和已有高亮差异，不重复扫描全页字符。
- 普通阅读模式继续允许滚动、缩放和系统长按选择。
- 对扫描版、无文字层或异常字体映射 PDF 返回明确提示，不伪造文本。

### 3.4 验收

- 在双栏首页从 `Simple Summary` 开始向下拖动，只选择右侧正文连续文本，不选择上方作者单位或左侧栏。
- 从一行中部拖到下一行中部，结果包含起始行后半段、完整中间行和结束行前半段。
- 反向拖动、单词点击和端点手柄调整结果正确。
- 选区文本顺序与视觉阅读顺序一致，翻译和解释收到的文本与高亮一致。
- 选字模式首帧构建和拖动更新在 Android 真机上无明显卡顿。

## 4. A+B 创新节点持久化

### 4.1 数据模型

扩展 `idea_candidates`：

- `source_type`：`graph_rule`、`mobile_ab` 或 `manual`
- `source_thread_id`、`source_message_id`
- `concept_a`、`concept_b`
- `answer_markdown`：保留完整分析正文

新增 `idea_paper_links` 表：

- `idea_id`
- `paper_id`
- `paper_title_snapshot`、`paper_path_snapshot`
- `citation_label`、`concept_role`
- `page_start`、`page_end`、`snippet`
- `similarity_score`、`content_hash`

论文标题、路径和证据必须保留快照，不能只依赖会随解除索引级联删除的 `papers` 外键。所有新增列提供默认值并通过幂等迁移添加；`IdeaCandidate` 对应新增字段全部为可选字段，旧数据库和旧前端仍可读取。

修改规则 Idea 刷新策略：

- `materialize_ideas` 只删除和重建 `source_type = 'graph_rule'` 的 `rule1`、`rule2`、`rule3`。
- `mobile_ab` 和 `manual` Idea 永久保留，除非用户明确删除。
- 移动会话 Idea 使用 `threadId + assistantMessageId` 生成稳定 ID，断线重试不会重复插入。

### 4.2 生成时机

1. A+B 检索先产生结构化论文证据。
2. Ollama 完整回答成功并写入移动会话。
3. 后端调用统一的 `save_mobile_innovation_idea`，写入概念、正文、证据与来源会话。
4. 保存失败不把聊天回答标记为失败；移动端显示“回答已完成，但 Idea 保存失败，可重试”。
5. 保存成功后发送可选 NDJSON `idea` 事件，并向桌面端发出 Idea 列表刷新事件。

### 4.3 多论文证据

- A、B 每侧默认最多保留 2 篇不同论文，整个 Idea 最多 4 篇本地论文。
- 标签扩展为 `[A1]`、`[A2]`、`[B1]`、`[B2]`；旧 `[A1]`、`[B1]` 保持兼容。
- 同一论文不能同时占用 A、B 两侧名额。
- 没有本地证据的一侧不创建论文节点或引用边。
- 论文节点代表实际论文证据，不把 embedding 向量本身伪装成论文。向量只负责检索和候选排序。

## 5. Idea Map Canvas 设计

### 5.1 节点与边

- `GraphNodeKind` 新增 `paper`。
- 移动 A+B Idea 的每篇唯一证据论文生成一个 `paper:{paperId}` 节点。
- 论文节点通过 `supports_idea` 边指向 `idea:{ideaId}`。
- 边的 `supportCount` 为该论文在 Idea 中的证据片段数；边详情展示标签、页码和片段。
- 规则 Idea 继续保留现有 Challenge、Module、Task、Pipeline 到 Idea 的 `resolves`、`inspired_by` 边。

### 5.2 视觉与交互

- Idea Map 增加 `Paper` 视觉泳道，布局为 `Paper / Concept -> Idea`。
- Paper 节点使用冷灰蓝色和 `PAPER` 标识，Idea 节点继续使用暖金色。
- `supports_idea` 使用由论文指向 Idea 的青金色实线箭头；概念启发边继续使用金色虚线。
- 点击 Paper 节点或证据边可打开对应 PDF，并定位首个证据页。
- 点击移动 A+B Idea 时显示 A/B 概念、来源会话、完整 Markdown、证据覆盖状态和论文列表。

### 5.3 验收

- 完成一次有两侧本地证据的 A+B 分析后，Idea Map 自动出现一个新 Idea。
- 至少两个不同 Paper 节点通过 `supports_idea` 指向该 Idea。
- 点击论文节点能够打开正确 PDF 和证据页。
- 重建索引、刷新规则 Idea 或重启桌面端后，会话 Idea 不丢失、不重复。
- 单侧或双侧无证据时只生成实际存在的论文节点，不出现伪造边。

## 6. 演示论文整理

### 6.1 建议展示的 6 篇

1. `Tejada-Lapuerta 等 - 2025 - Causal machine learning for single-cell genomics.pdf`
   - 保留现有已审核图谱、因果与单细胞示例。
2. `Tan 等 - 2025 - Integration of Single-Cell Analysis and Bulk RNA Sequencing Data Using Multi-Level Attention Graph N.pdf`
   - 作为 PDF 双栏选字、整页翻译和 GNN 生物医学应用示例。
3. `Raj 等 - 2012 - A network diffusion model of disease progression in dementia.pdf`
   - 作为 AD 研究对象侧的网络传播机制证据。
4. `Liu 等 - 2024 - TP-GNN Continuous Dynamic Graph Neural Network for Graph Classification.pdf`
   - 作为 GNN 方法侧证据。
5. `Ali 等 - 2025 - Graph neural networks in alzheimer's disease diagnosis a review of unimodal and multimodal advances.pdf`
   - 作为 AD+GNN 已有工作的边界与反例检查；同哈希的 `(2)` 副本不保留。
6. `2024 - Self-explainable graph neural network for alzheimer disease and related dementias risk prediction a.pdf`
   - 作为可解释 AD+GNN 实验论文。

### 6.2 演示可见集与最终物理清理

在应用数据目录增加 `demo_library_manifest.json` 或等价数据库偏好，记录：

- 稳定 `paperKey` 或内容哈希
- `visibleInDemo`
- `pinned`
- `hiddenAt`
- 中文隐藏原因

companion service 读取持久化的 `demo_library.json`，在线时只返回 6 篇演示论文；移动端在线时不再把清单之外的旧离线缓存合并回列表，离线时仍可打开已有缓存。

应用通过 `demo_library.json` 固定 6 篇演示论文的可见性。根据用户明确授权，工作区中其余 114 篇 PDF 已永久删除，释放约 670.04 MiB；保留文件的原路径、`paper_id`、`workspace_pdf_id`、知识卡片、会话引用或 Idea 证据不变。

为使 AD+GNN 演示真正产生双路证据，至少完成 Raj、TP-GNN、Ali 和 Self-explainable GNN 的 Research Memory 索引；保留 Tejada 的现有审核结果，并完成 Tan 当前 pending 索引或明确把它仅作为 PDF 阅读样例。

### 6.3 可选的磁盘归档

只有用户明确要求释放磁盘时才执行：

1. 完全退出桌面端，解析并验证工作区绝对路径。
2. 生成包含原路径、目标路径、大小、SHA-256、卡片引用、会话引用和 Idea 引用的预览清单。
3. 在工作区之外创建 `paper_archive/demo_cleanup_<时间戳>`，并备份 SQLite 与 LanceDB。
4. 先复制并校验归档哈希，再通过统一事务流程解除索引和切换文件位置。
5. 任何阶段失败均恢复数据库和文件；不得把文件移动与解除索引拆成两个互不关联的操作。

### 6.4 回滚

- 物理删除不可通过应用即时回滚；需要从外部备份重新导入。保留的 6 篇仍沿用原路径和稳定 ID。
- 磁盘归档根据清单恢复原路径；如索引数据也需恢复，先退出桌面端，再恢复同时间戳 SQLite 与 LanceDB 备份。

## 7. 实施顺序

1. 实现并测试 `VisualTextMap`、线性选区和端点手柄。
2. 迁移 Idea 数据模型，修复规则刷新误删持久 Idea 的问题。
3. 在 A+B 完成链路中持久化 Idea，并扩展多论文标签与流式协议。
4. 在 Idea Map 增加 Paper 节点、`supports_idea` 边、证据详情和 PDF 跳转。
5. 更新 README 与设计规范。
6. 启用 6 篇演示可见集；在用户明确授权后物理删除其余 114 篇 PDF。
7. 建立最小演示索引并完成 Android 真机与桌面 Idea Canvas 联调。

- Web 与移动 TypeScript 检查通过。
- Rust 格式、检查和移动协议/Idea 持久化测试通过。
- 桌面端 NSIS 与 Android release APK 构建通过。

- 使用“能否在 AD 上使用 GNN 分析”完成真机验收：确认概念、获得多论文证据、聊天下方显示引用卡，并在桌面 Idea Map 看到论文节点指向创新点。
