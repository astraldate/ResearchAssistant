# Rust OCR 与移动横屏适配方案

## 目标定义

在不覆盖原 PDF、不引入 Python 运行时的前提下，吸收参考 OCR 项目的逐页处理和断点恢复能力；同时解除移动端竖屏锁定，为 Android 平板提供更适合阅读的横屏布局。用户后续明确要求取消 OCR SHA-256 门禁。

## 功能分解

### 1. 可恢复 OCR 作业管线

- 为 OCR 页面处理定义严格引擎接口，使预检、渲染、识别、版面排序和索引能够独立测试与替换。
- 分离原始 OCR 页面缓存和最终版面 Sidecar，健康缓存按源签名与模型版本跳过。
- 任务按页持久化完成页、失败页、重试次数、暂停与取消状态，应用重启后从已完成页继续。
- 统一旋转页的坐标规范化，最终 Token 坐标保持在当前显示页面的 `0–1` 范围。

### 2. 真实推理下载边界

- PDFium、ONNX Runtime、检测模型、识别模型、字典和版面模型只从内置 HTTPS 清单下载。
- 按用户要求不再计算或校验 SHA-256；保留非空文件、HTTP Content-Length 和可选预期大小检查。
- 当前不自动下载模型，不把模拟引擎或作业骨架描述为真实 OCR。
- 原 PDF 永不写回；移动端和桌面端只消费应用数据目录中的结构化 Sidecar。

### 3. 移动响应式基础

- Expo 方向改为跟随设备，Android Manifest 移除竖屏锁定。
- 新增统一布局判定：短边小于 600dp 始终视为手机；平板横屏再按 900dp 与 1200dp 区分 expanded 和 large。
- `ScreenShell` 支持最大内容宽度、紧凑横屏页头和四边安全区。
- 平板横屏 Tabs 移至左侧，手机与平板竖屏保留底部栏。

### 4. 阅读优先布局

- PDF 阅读器在平板横屏使用左侧文档、右侧工具区；竖屏和手机继续使用底部工具栏。
- 保留现有 PDF 容器测量与页码状态，旋转不得通过改变组件 `key` 强制重建。
- 论文列表在 expanded 使用两列，在 large 且单卡宽度足够时使用三列。
- 后续将聊天会话、知识库详情与知识编辑器升级为平板主从布局。

## 实施步骤

1. 扩展 OCR 类型、存储和作业执行器，补充缓存、恢复、重试、取消与旋转坐标测试。
2. 注册必要的桌面作业命令；真实推理未就绪时返回明确中文安全原因。
3. 新增移动响应式布局工具与纯函数测试，同时解除双重方向锁定。
4. 修改 Tabs 与 `ScreenShell`，再实现 PDF 阅读器左右分栏和论文网格。
5. 运行 Rust 格式、编译和单元测试，以及 Web/移动 TypeScript、移动纯函数测试、Prettier、冲突标记和差异空白检查。

## 验收标准

- 重启后的 OCR 作业可保留完成页和失败页并恢复为暂停；健康页面缓存不会重复处理，失败页可以定点重试。
- 清单外或非 HTTPS 运行库仍不可下载；清单内资产不再要求密码学哈希。
- `412×915dp` 手机竖屏和 `915×412dp` 手机横屏保持紧凑布局；`1024×600dp`、`1280×800dp` 平板横屏进入双栏。
- 平板旋转后 PDF 当前页、缓存状态、AI 结果和应用导航状态不因组件重建丢失。
- Rust OCR 测试实际出现在 `cargo test --lib` 输出中，全部规定的静态与格式门禁通过。

## 本增量不做

- 不自动下载 PDFium、ONNX Runtime 或 PP-DocLayout；下载仍需由用户主动触发。
- 不实现隐藏文字层或覆盖原 PDF。
- 不构建正式安装包，不调用 Ollama，不写入 Research Memory，不实现加密备份。
